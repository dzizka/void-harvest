# Void Harvest — notes for Claude

- The owner communicates in **Slovak**; commit messages are Slovak. The game is bilingual (English / Slovak, picked in the hangar or Menu → Jazyk · Language; default from browser language). Typical flow: user asks for analysis/proposals first, then says "pokračuj" to implement step by step.
- Plain HTML5 Canvas + vanilla JS, no build step needed to run. `index.html` loads `css/*.css` and `js/**/*.js` as **classic scripts in a fixed order sharing one global scope** (no ES modules, so it runs from `file://`). Every JS file starts with `'use strict';`.
  - Top-level code in a file may only call functions from files loaded **earlier**; function declarations are not hoisted across files. Startup calls live in `js/main.js`.
  - New file → add its `<script>` tag to `index.html` in the right place; `tools/build.js` picks it up automatically.
- **i18n:** source text in code is Slovak. Every user-facing string must be wrapped: `_L('text')` for literals, `` _T`text ${x}` `` for templates (dictionary keys use `{0}`, `{1}` for the `${…}` slots). English goes into `js/i18n-en.js` (key = exact Slovak source). Static text in `index.html` is translated by `translateStatic()` (text nodes + title/aria-label). Never split a word across a template boundary; keep whole phrases in one string. Don't use local variables named `_L`/`_T`. `npm run i18n` lists Slovak strings without an English entry (only those with diacritics — check plain-ASCII Slovak words like "rudy" by hand). Language switch reloads the page (`setLang`).
- Auto-combat / auto-mining (lazy play) default OFF; toggles live in Menu (≡) and on F / R.
- Touch mode (`js/ui/touch.js`, `css/touch.css`): `TOUCH.on` (pref auto/on/off in Menu, stored in `void-harvest-touch`) adds `body.touch`; everything mobile is gated by it so desktop stays unchanged. Floating sticks write `input.mv` / `input.aim`; `touchAim()` parks `input.mx/my` ahead of the ship so mouse-aimed code keeps working. Action pad + context button (`G.interact`) refresh in `touchHud()`. New touch games start with auto-combat/mining ON; portrait pauses the game. Panels go full screen; hover tooltips are replaced by a tap sheet (`itemSheet` on `#tip.sheet`, capture-phase click handlers for `#grid`, `#eslots`, `#craftBody [data-mv]`, `.info[title]`), long-press never salvages.
- Gamepad (`js/ui/gamepad.js`): `PAD` state in state.js, `padPoll()` each frame from main.js, `padAim()` from `updatePlayer` (parks `input.mx/my` like touch). Active from the first pad input until the real mouse moves. Outside flight (`padScope()`: hangar, open panel, death screen, Menu) the D-pad / left stick moves a `.padfocus` ring (spatial nav), A clicks, X dispatches contextmenu, B closes. Interface scale + screen shake: `UIS` in background.js (`void-harvest-ui`), CSS `zoom: var(--ui)` on #hud/.bay/#tip/#dead (not in touch mode). Rarity marks `RARITY[].mark` via `rarMark(it)`. First touch run defaults graphics to `mid` (only if no stored choice).
- PWA: `manifest.json` + `sw.js` (root; registered from main.js only over http(s), not from file:// or dist/). Install caches every script/style listed in index.html plus fonts; code is network-first, `assets/` cache-first with background refresh, music is not cached. Fonts are self-hosted in `assets/fonts/` via `css/fonts.css` (no Google Fonts). Main loop runs up to 3 substeps of ≤ 0.05 s when FPS drops below 20.
- Per-frame lists are compacted in place with `prune(arr, keep)`; ambient/trail particles check `fxFull()` (cap 1 600).
- Pseudo-3D sprites (`js/render/models3d.js`): sheets in `assets/sprites/*.webp` pre-rendered from CC0 models in `assets/models/` (credits in `assets/CREDITS.md`) by `tools/render3d/sheet.js` + `specs.json` (needs `npm i --no-save three@0.169.0`, global Playwright). Frame i = angle +i/f·2π (clockwise), ships have 3 bank rows. `spr3d(key)` lazy-loads and returns null until ready → callers fall back to the vector drawing. Toggle `GFX.models` (Menu → 3D modely). `tools/build.js` rewrites `SPR_BASE` to `../assets/sprites/` for dist.
- Save safety: item ids are account-wide (`ACC.itemId`, `fixItemIds` on start), rewards go through `giveItem()` (hold → stash → `ACC.mail`), paid runs store `P.refund` until the first kill, the last tab that starts a game owns the save (`TAB.ro` blocks saving elsewhere), unparsable saves are copied to `…-corrupt-<ts>`.
- Audio (`js/core/audio.js`): sound effects synthesised with WebAudio, `sfx(name, x, y, vol)` with per-sound rate limits, voice cap and distance falloff; music = licensed tracks in `assets/music/` (ogg + mp3 fallback, credits in hangar + `assets/CREDITS.md`) picked by `musMood()` (hangar / haven / calm / sector / gate / boss / emergency / death), streamed via HTMLAudio and crossfaded in `audioTick` (runs every 0.1 s from the main loop); settings `AUD.set` (Menu → Zvuky / Hudba, key `void-harvest-audio`). Context starts on the first user gesture.
- Key globals: `G` (session/world state), `P` (player ship), `ACC` (account: stash, achievements, leaderboards). `computeStats()` in `js/core/stats.js` is the single source of truth for stats (gameplay and tooltip comparison). Saves: `localStorage` keys `void-harvest-account-v1` and `void-harvest-save-v1:<cls>`; keep old saves loading (migrate in `restoreSave`/`loadAccount`).
- Abilities live in `js/systems/abilities.js`: `DODGES` (Space, per ship), `SKILLS` (4 per ship, 2 equipped on Q / Shift via `P.skill.sel`), skill points `P.skill.rk` (1 per 5 levels), modifiers `P.skill.mod`; `skDmg(id)` / `skillCd(id)` apply upgrades and the `skDmg` / `skCdr` affixes.
- Materials and home base (account-wide `ACC.mats`, `ACC.base`) live in `js/systems/base.js`: modules (refinery, lab, hangar, greenhouse), research bonuses applied in `computeStats` via `researchFx`, expeditions and refinery run on real time (`Date.now()`, max 8 h), stimulants `P.stim`.
- Exploration in `js/systems/exploration.js`: scanner (C, `G.ex.scan`), per-visit anomalies `G.ex.anoms`, 14 ancestor beacons (`beaconList`, account-wide `ACC.beacons`, bonuses via `beaconFx` in `computeStats`), sector hazards `SECTOR_HAZ` (flares, black holes, radiation clouds).
- Story & seasons in `js/systems/story.js`: 8 chapters `CHAPTERS` (NPCs in `NPCS`, unlock by level, progress per character in `P.story`; dialog panel `dlg`). Other systems report through `gameEvent(type, data)` (kill, gate, arch, anom, beacon, fort, storm, horde, dock); state-like steps are checked in `tickStory`. Seasons are 28 days from `SEASON_EPOCH`, account-wide in `ACC.season` (30 tiers of 100 points, `claimSeason`, journey `SEASON_JOURNEY`), rotating rule `seasonMod(k)` (storm / elites / greater / gold).
- Dungeon-like modes reuse `G.dungeon` with flags (`nm`, `pinnacle`, `climb`, `weekly`, `vault`, `rush`, `horde`). Open-world events in `js/systems/endgame-events.js`: Void Storm (`G.storm`, embers, cursed chests), strongholds (`G.forts`, `G.siege`, outposts count as safe zones via `isSafe`), Void Horde (`G.dungeon.horde`, boons `G.dungeon.hb`, read with `hb(k)`).
- Tooling: `npm run lint` (tools/lint.js, ESLint 8 over all scripts bundled in index.html order, maps back to file:line; also duplicate keys in i18n-en.js) and `npm run balance -- --min 45 [--cls a,b] [--tier N] [--lv L] [--deep]` (tools/balance.js, headless bot table). Helpers: `nearestEnemy(x, y, r, skip)` in util.js, `HOLD_MAX` (cargo size) in game-data.js.
- Testing: `npm test` (builds `dist/void-harvest.html`, then `tools/smoke.js` plays every ship in both versions and opens all panels; fails on NaN/Infinity in P, P.stats, ACC.mats or enemies). For balance/features write ad-hoc Playwright scripts that drive the game via globals (`startGame`, `cheatLevels`, `cheatTopGear`, `loadSector`, `spawnEnemy`, `update(dt)`, `openPanel`) and review screenshots. Fonts from Google should be blocked in headless tests (`page.route(/fonts\.g/, r => r.abort())`).
- Onboarding gates (`js/systems/journal.js`): `UNLOCK` levels per tab key (craft 5, base 8, season 10, chal 12), `isUnlocked(k)` uses account level `accLvl()` (best of all ships), `gateTabs` / `lockedMsg` for tab buttons; contracts and the chapter 1 dialog wait for `tutDone()`.
- Audit and improvement plan: `docs/AUDIT.md` (phases 1–5, done) and `docs/AUDIT-2.md` (phases A–F, proposed; each change lists its risk and mitigation). Developer docs in Slovak: `docs/TECHNICKA-DOKUMENTACIA.md`.
- After changes: run `npm test`, commit with a Slovak message, push to `main` (GitHub Pages serves the repo root at https://dzizka.github.io/void-harvest/).
